# 予定の登録・編集

ファイル：`src/pages/event-form/EventFormPage.jsx`
ブランチ：`event-form`

## 作るもの

- タイトル・日付・時間・場所・種類・チケット・メモを入力して、予定を保存できる
- 登録（`/events/new`）と編集（`/events/:id/edit`）で、このページを使い回す。編集のときは、開いたときに今の内容が入っている
- 「キャンセル」で保存せずに戻る

使うデータ：

| コレクション | フィールド |
| --- | --- |
| `events` | `uid`・`title`・`date`・`time`・`place`・`type`・`ticket`・`memo`・`oshiId`・`createdAt` |

それぞれの中身は [設計書](../design.md) の「データの形」にある。種類とチケットの状態の名前は `src/eventTypes.js` から読み込んで使う（自分で書き写さない）。

カレンダーと予定の詳細は、ほかの人が同時に作っている。保存できたかは Firebase のコンソールで確かめる。

## 手順

### ステップ 1：入力欄を置く

「`title`・`date`・`time`・`place`・`type`・`ticket`・`memo` という state を作る。`type` の最初は `ライブ・イベント`、ほかは空の文字 `""`」

「それぞれの入力欄を、ラベル付きで置く。日付は `<input type="date">`、時間は `<input type="time">`、メモは `<textarea>`」

「種類は `<select>` にして、`src/eventTypes.js` の `EVENT_TYPES` の名前を選択肢に並べる」

「チケットも `<select>` にして、いちばん上に『なし』（値は `""`）、その下に `src/eventTypes.js` の `TICKET_STATUSES` を並べる」

- 全部の入力欄に入力・選択ができれば OK
- 参考：書き方の見本「入力欄」

レシピには `<select>` と日付の入力欄の見本がないので、ここに置いておく。どちらも、ふつうの入力欄と同じく `value` と `onChange` で state とつなぐ。

```jsx
<input type="date" value={date} onChange={(e) => setDate(e.target.value)} />

<select value={type} onChange={(e) => setType(e.target.value)}>
  {EVENT_TYPES.map((eventType) => (
    <option key={eventType.name} value={eventType.name}>
      {eventType.name}
    </option>
  ))}
</select>
```

`<input type="date">` の値は `"2026-12-24"`、`<input type="time">` の値は `"18:00"` の形の文字列になる。そのまま保存する。

### ステップ 2：保存する（登録）

「『保存』ボタンを置く。`saveEvent` という関数を作る。中身は、`title` か `date` が空なら『タイトルと日付を入力してください』と出して終わる。空でなければ、`events` コレクションに、入力した 7 つと、`uid`（自分の UID）・`oshiId`（`""`）・`createdAt`（`Date.now()`）を足す。足したらカレンダー（`/`）に移る」

- 入力して「保存」を押すと、コンソールの `events` に 1 件増えて、カレンダーに移れば OK
- コンソールで、フィールドが 10 個そろっていれば OK（時間などを空にしたときも、`""` で入っている）
- タイトルを空にして「保存」を押すと、メッセージが出て、保存されなければ OK
- 参考：書き方の見本「送信」、レシピ「作る」

### ステップ 3：キャンセルボタンを置く

「『キャンセル』ボタンを置く。押すと、保存せずに前のページに戻る」

- カレンダーから「予定を追加」でこのページに来て「キャンセル」を押すと、カレンダーに戻れば OK
- 参考：書き方の見本「ページの移動」（前のページに戻るのは `navigate(-1)`）

### ステップ 4：編集のとき、今の内容を入れる

「URL の `id` を取る。`id` があれば、画面が表示されたときに 1 回だけ、`events` からその `id` の予定を 1 件取ってきて、7 つの state に入れる」

「見出しは、`id` がなければ『予定の登録』、あれば『予定の編集』にする」

- コンソールの `events` から、ステップ 2 で保存した予定のドキュメント ID をコピーして、ブラウザで `/events/コピーしたID/edit` を開く。見出しが「予定の編集」で、保存した内容が入力欄に入っていれば OK
- `/events/new` を開くと、見出しが「予定の登録」で、入力欄が空なら OK
- 参考：書き方の見本「1 件だけ取ってくる」「ページの移動」（URL の `id` は `useParams` で取る）

### ステップ 5：編集のとき、書き換えて保存する

「`saveEvent` を直す。`id` があれば、`events` のその予定の 7 つのフィールドを書き換えて、`/events/その id` に移る。`id` がなければ、今までどおり足す」

- ステップ 4 の画面でタイトルを変えて「保存」を押すと、コンソールでタイトルが変わっていれば OK。予定が増えていなければ OK
- 保存のあと「予定の詳細」の見出しのページに移れば OK
- 参考：レシピ「変える」

### ステップ 6：見た目を整える

「ラベルと入力欄を 1 行ずつ縦に並べて、入力欄の幅をそろえる。『保存』と『キャンセル』は横に並べる」

- 入力しやすい見た目になれば OK
- 参考：書き方の見本「CSS」
