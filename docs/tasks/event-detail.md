# 予定の詳細

ファイル：`src/pages/event-detail/EventDetailPage.jsx`
ブランチ：`event-detail`

## 作るもの

- URL の `id` の予定の、タイトル・日付・時間・場所・種類・チケット・メモが出る
- 種類は、その種類の色の枠で囲んで出る。空の項目は出ない
- 「編集」ボタンで編集に移る。「削除」ボタンで、確認のあと削除してカレンダーに戻る
- カレンダーに戻るリンクがある

使うデータ：

| コレクション | フィールド |
| --- | --- |
| `events` | `title`・`date`・`time`・`place`・`type`・`ticket`・`memo` |

それぞれの中身は [設計書](../design.md) の「データの形」にある。

予定を保存するページ（予定の登録・編集）は、ほかの人が同時に作っている。できるまでは、Firebase のコンソールで手で入れたデータで確かめる。

## 手順

### ステップ 1：確かめ用の予定を手で入れる

Firebase のコンソールで、`events` コレクションにドキュメントを 1 件足す。フィールドは次のとおり。

| フィールド | 型 | 値 |
| --- | --- | --- |
| `uid` | string | 自分の UID（コンソールの Authentication の画面でコピーする） |
| `title` | string | `横浜公演` |
| `date` | string | `2026-12-24` |
| `time` | string | `18:00` |
| `place` | string | `横浜アリーナ` |
| `type` | string | `ライブ・イベント` |
| `ticket` | string | `当選` |
| `memo` | string | `グッズは開演前に買う` |
| `oshiId` | string | （空でよい） |
| `createdAt` | number | `1763450000000` |

足したら、そのドキュメント ID をコピーしておく。

- ブラウザで `/events/コピーしたID` を開くと、「予定の詳細」の見出しが出れば OK

### ステップ 2：予定を 1 件取ってくる

「URL の `id` を取る」

「`event` という state を作る。最初は `null`」

「`getEvent` という関数を作る。中身は、`events` からその `id` の予定を 1 件取得して、`event` に入れる」

「画面が表示されたときに 1 回だけ、`getEvent` を呼ぶ。`event` が `null` の間は『読み込み中…』と出す」

- 開いた直後に一瞬「読み込み中…」が出て、そのあと見出しだけの画面になれば OK
- 参考：書き方の見本「1 件だけ取ってくる」「読み込み中と失敗」「ページの移動」（URL の `id` は `useParams` で取る）

### ステップ 3：予定の中身を出す

「タイトルを見出しにする。その下に、日付を『2026年12月24日』の形にして、時間と並べて出す」

「場所・チケット・メモを、それぞれ『場所』『チケット』『メモ』のラベル付きで出す。中身が `""` の項目は、ラベルごと出さない」

- ステップ 1 で入れた内容が全部出れば OK
- コンソールで `memo` を空にして再読み込みすると、「メモ」が出なくなれば OK
- 日付は文字列のまま `-` で区切って組み立てる（`new Date()` に入れると 1 日ずれることがある）
- 参考：書き方の見本「一覧と出し分け」

### ステップ 4：種類を色の枠で囲んで出す

「種類の名前を出して、`src/eventTypes.js` の `getTypeColor` に `type` を渡して返ってきた色で、枠線を付ける」

- 「ライブ・イベント」がピンクの枠で囲まれて出れば OK
- コンソールで `type` を `締切` に変えて再読み込みすると、赤い枠になれば OK
- 参考：書き方の見本「CSS」（色を JavaScript で決めるときは `style={{ borderColor: 色 }}`）

### ステップ 5：「編集」ボタンを置く

「『編集』ボタンを置く。押すと `/events/その id/edit` に移る」

- 押すと「予定の登録・編集」の見出しのページに移れば OK（中身はほかの人が作っている）
- 参考：書き方の見本「ページの移動」

### ステップ 6：「削除」ボタンを置く

「『削除』ボタンを置く。押すと『この予定を削除しますか？』と確認を出し、OK なら `events` からその予定を削除して、カレンダー（`/`）に移る」

- 「削除」を押して確認でキャンセルすると、何も起きなければ OK
- OK を押すと、カレンダーに移って、コンソールの `events` からその予定が消えていれば OK
- 確かめたら、ステップ 1 と同じ予定を入れ直しておく
- 参考：レシピ「消す」（確認は `window.confirm("この予定を削除しますか？")` が `true` のときだけ消す）

### ステップ 7：カレンダーに戻るリンクを置く

「カレンダー（`/`）に戻るリンクを置く」

- 押すとカレンダーに戻れば OK
- 参考：書き方の見本「ページの移動」

### ステップ 8：見た目を整える

「ラベルを薄い色の小さい文字にして、中身と縦に並べる。『編集』と『削除』は横に並べて、『削除』は赤い文字にする」

- 読みやすい見た目になれば OK
- 参考：書き方の見本「CSS」
