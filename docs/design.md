# 設計書

企画の話し合いの結果は [企画まとめ](plan.md) にある。この設計書は、それを作れる形に決め直したもの。食い違ったらこっちに従う。

## どんなアプリか

推し活の予定を、カレンダーでまとめて管理できるアプリ。

- 予定をカレンダーに登録する。予定がある日には、推しのアイコンが出る
- アイコンの**枠の色**で、予定の種類（ライブ・締切など）がわかる
- 予定に写真をひもづけて、その日のアルバムにする（3 周目）

## ページ

| ページ | URL | ファイル | 周 |
| --- | --- | --- | --- |
| ログイン | — | `src/pages/login/LoginPage.jsx` | できている |
| カレンダー | `/` | `src/pages/home/HomePage.jsx` | 1 周目 |
| 予定の登録・編集 | `/events/new`・`/events/:id/edit` | `src/pages/event-form/EventFormPage.jsx` | 1 周目 |
| 予定の詳細 | `/events/:id` | `src/pages/event-detail/EventDetailPage.jsx` | 1 周目 |
| 推しの登録・編集 | `/oshis` | `src/pages/oshis/OshiPage.jsx` | 2 周目 |
| 写真 | — | 予定の詳細に足す | 3 周目 |

1 周目の 3 ページで、予定の登録・表示・編集・削除ができる（スケジュール帳として使える）。ここまでで発表できる状態になる。

画面の流れ：カレンダー → 日付を押す → 予定を押す → 予定の詳細 → 編集

## データの形

### `events`（予定）

| フィールド | 型 | 中身 |
| --- | --- | --- |
| `uid` | 文字列 | 登録した人 |
| `title` | 文字列 | 予定の名前（例：横浜公演） |
| `date` | 文字列 | 日付。`"2026-12-24"` の形 |
| `time` | 文字列 | 時間。`"18:00"` の形。決まっていなければ `""` |
| `place` | 文字列 | 場所。なければ `""` |
| `type` | 文字列 | 種類（下の表のどれか） |
| `ticket` | 文字列 | チケットの状態（下の表のどれか）。チケットがない予定は `""` |
| `memo` | 文字列 | メモ。なければ `""` |
| `oshiId` | 文字列 | どの推しの予定か（`oshis` のドキュメントの id）。1 周目は `""` |
| `createdAt` | 数値 | 登録した日時（`Date.now()`） |

日付と時間は、`<input type="date">`・`<input type="time">` が返す文字列をそのまま保存する。日付を文字列にしておくと、カレンダーのマスの日付と `===` で比べられる。

**種類**は次の 5 つ。**1 文字も変えずにこのとおり使う**（カレンダーはこの名前で色を決める）。

| 種類 | 枠の色 |
| --- | --- |
| `ライブ・イベント` | ピンク |
| `締切` | 赤 |
| `発売日` | 黄 |
| `配信・放送` | 青 |
| `その他` | グレー |

**チケットの状態**は次の 4 つ：`申込済み`・`当選`・`入金済み`・`発券済み`

種類・色・チケットの状態は、`src/eventTypes.js` に書いてある。どのページもここから読み込んで使い、自分のページに書き写さない。

### `oshis`（推し）：2 周目

| フィールド | 型 | 中身 |
| --- | --- | --- |
| `uid` | 文字列 | 登録した人 |
| `name` | 文字列 | 推しの名前 |
| `icon` | 文字列 | 絵文字 1 つ（例：🐰） |
| `createdAt` | 数値 | 登録した日時（`Date.now()`） |

### 写真：3 周目

保存先（Firebase Storage にするか、Firestore に入れるか）が決まってから書く。

### どのページが何を使うか

| ページ | `events` | `oshis` |
| --- | --- | --- |
| カレンダー | 読む | 読む（2 周目） |
| 予定の登録・編集 | 作る・1 件読む・直す | 読む（2 周目） |
| 予定の詳細 | 1 件読む・消す | 1 件読む（2 周目） |
| 推しの登録・編集 | — | 作る・読む・直す・消す |

一覧で読むときは、どれも**自分の分だけ**（`uid` が自分のもの）を読む。`events` は `date` の古い順、同じ日の中は `time` の早い順に並べる。

## 共通の決まり

- ほかの人のページのファイルは書き換えない。`src/eventTypes.js` と `src/App.jsx` も書き換えない（直したいときは相談する）
- 日付は文字列のまま扱う。`new Date("2026-12-24")` で日付に変えると、時差で 1 日ずれることがある

## 各ページ

### カレンダー

- 月表示のカレンダーを、日曜始まりの 7 列で出す。上に「2026年12月」のように年月を出す
- 「前の月」「次の月」ボタンで月を切り替える。最初は今月を出す
- 予定がある日のマスに、丸い枠を出す。枠の色は予定の種類の色
  - 1 周目は推しがまだないので、枠の中は空でよい（2 周目に推しのアイコンを入れる）
  - 1 日に 4 件以上あるときは、3 つまで出して、残りは「+2」のように数だけ出す
- 日付のマスを押すと、カレンダーの下にその日の予定が並ぶ（時間・タイトル）。最初は今日の予定を出す
  - 予定を押すと、その予定の詳細に移る
  - 予定がない日は「予定はありません」と出す
- 「予定を追加」ボタンで、予定の登録に移る
- ログインしている人の名前と、ログアウトのボタンを置く（今あるものを残す）

### 予定の登録・編集

- 登録（`/events/new`）と編集（`/events/:id/edit`）で同じページを使う。URL に `id` があれば編集
- 入力欄：タイトル・日付・時間・場所・種類・チケット・メモ
  - 種類とチケットは選択式（`<select>`）。チケットのいちばん上は「なし」（値は `""`）
  - タイトルと日付は必須。空のまま「保存」を押したら、保存せずに「タイトルと日付を入力してください」と出す
- 登録のとき：「保存」で `events` に足して、カレンダーに戻る
- 編集のとき：開いたときに今の内容が入力欄に入っている。「保存」で書き換えて、その予定の詳細に戻る
- 「キャンセル」で、保存せずに前のページに戻る

### 予定の詳細

- URL の `id` の予定を 1 件取ってきて、タイトル・日付・時間・場所・種類・チケット・メモを出す
  - 種類は、その種類の色の枠で囲んで出す
  - 空の項目（時間・場所・チケット・メモ）は出さない
- 「編集」ボタンで、その予定の編集に移る
- 「削除」ボタンで、確認を出してから削除し、カレンダーに戻る
- カレンダーに戻るリンクを置く

### 推しの登録・編集（2 周目）

- 名前とアイコン（絵文字）を入れて登録する。登録済みの推しを並べ、それぞれ編集・削除できる
- あわせて、予定の登録・編集に推しを選ぶ欄（アイコンを並べて押して選ぶ）を、カレンダーと予定の詳細に推しのアイコンを足す。誰がどこを直すかは 2 周目の担当シートで決める
